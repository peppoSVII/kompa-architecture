The dividing rule
-----------------

    DATA          →  client talks to the database directly,
                     authorised by versioned security rules

    SIDE EFFECTS  →  server only
                     (push, AI, quotas, privileges)


Why the server cannot be removed
--------------------------------

  · the push credential can send to EVERY user of the app,
    so it cannot live in a downloadable binary
  · the AI key must not live in the client
  · "who are you / are you a member / does this exist" must be
    answered by something the client cannot forge


Why the server is stateless
---------------------------

  · it can run as many instances as needed
  · it can scale to zero when idle
  · a restart loses nothing, because nothing important is in memory
